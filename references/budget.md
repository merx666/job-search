# 浏览预算与续接

预算是已确认查询范围内的整轮上限，不是每条命令的额度，也不是必须用完的配额。达到各平台目标即可停止。登录、验证码、平台冷却、模型限流的停止规则优先于剩余额度。

## 新计划与旧计划

`plan` 对省略或为 null 的预算生成具体整数：

- 令 Q 为去重后的关键词数 × 城市数，T 为本轮最大平台岗位目标。
- 结果页：`max(6, 2×Q, 3×ceil(T/5))`，最多支持 60。
- 详情尝试：`max(30, 6×T)`，最多支持 600。
- 超过支持范围时报错并拆轮，不静默漏搜。所有平台使用计划中展示的上限。

例如 3 个关键词、1 个城市、每平台 5 岗，默认 6 个结果页与 30 次详情尝试。前 3 页覆盖各关键词，留下 3 页用于后续筛选。每平台 20 岗、1 组查询时为 12 页与 120 次详情尝试。复杂目标可能仍达不到数量；更多浏览不能创造缺失的事实。

显式数字优先，包括旧计划的 3/10。重新读取旧计划不改预算或 confirmation_id。只改目标数也保留已有显式预算。需要重新估算时运行 `plan --input 原计划 --auto-budget --out 新计划`，或用 `--pages 12 --details 60` 指定新上限；输出变化给用户确认后才使用。旧计划的同意不自动授权更大的预算。

## 小批次执行

1. `scan` 首轮自动收集每组查询的第一页。之后用 `worklist` 读取缺口、`budget` 和最多 5 条 `detail_queue`；它是待办建议，不会自行打开详情。
2. 优先处理已有候选，避免继续堆积尚未核实的列表。队列排除硬条件失败项及 `detail_urls` 中已经尝试的链接，优先排序分高的候选。分数不是录用概率。
3. 每批最多 5 次详情尝试，或 1 个新结果页；每批落盘并重算。上限内无需再次询问。找到足够岗位后不继续花剩余预算。
4. 仍在加载的详情先在同页有界等待并再观察一次，合计不超过 8 秒，不刷新。成功才增加 `details_read`；失败同样消耗一次 `details_attempted`。再次打开或重新导航该详情是新尝试，也计入上限。连续 3 次失败先诊断页面/原 receipt，避免把整批预算浪费在加载页。
5. 结果页额度耗尽但尚有详情额度时继续已有候选；详情耗尽但有结果页额度时继续原查询。`audit_budget` 表示缺计数，先查已有记录，不代表申请更高额度或重扫。

## 状态记录与停止

状态例子（不是实际搜索结果）：

```json
{
  "boss": {
    "status": "ok",
    "queries": [{"keyword": "会计", "city": "上海", "status": "ok", "pages": 2}],
    "details_attempted": 2,
    "details_read": 1,
    "detail_urls": ["https://www.zhipin.com/job_detail/example-1.html", "https://www.zhipin.com/job_detail/example-2.html"],
    "note": "合成示例：第一个详情读到正文；第二个等待后仍在加载。"
  }
}
```

结果页使用量取 `queries[].pages` 之和；也可提供 `pages_read`，二者都有时必须一致。未提供计数时报告显示“未记录”，不会当成 0 或已耗尽。`budget_exhausted` 与 `results_exhausted` 都须有两类用量；即使没有候选，“结果已耗尽”也必须记录至少 1 个实际搜索结果页。列表重复读取/导航也计入结果页；只读同页加载状态或 receipt 不额外算一页。预检不算岗位结果页。

`detail_urls` 记录已尝试的链接，`details_attempted` 计所有尝试，含同链接重试；`details_read` 计成功读取。链接去重数不得超过尝试数。没有剩余结果页（或确实 results_exhausted），且详情额度用完或没有尚未尝试的可核实候选时，才可交付不足。仍缺硬条件证据的岗位保持待核实/排除。

若已有至少 3 个完整详情都缺同一硬条件（如发布时间），先查看这些正常页面及自然响应里是否真的展示该字段。若仍缺，报告写明样本数、缺失字段和影响，不能推断整个平台永远不提供；剩余额度只用于尚未尝试、可能补证的候选。不要为了数量改用刷新时间、扩大目标方向或降低时效要求。

## 断点续接

恢复先读取已有 plan、raw/enriched jobs、platform-status、next-actions 和未决 request receipt。合并旧候选，累加原 `queries[].pages` 和详情计数，保留已尝试链接；输出到新目录不能重置额度。

- 查询已经读过第一页：由 Agent 复用当前标签，从已观察的下一页或未尝试详情继续，不能再次 `scan` 把首页当新覆盖。
- `scan --only` 适合登录后尚未实际执行的查询。它不会自动导入旧目录的计数；若恢复平台已有采集记录，先合并账目并由 Agent 按余量续接。不能通过重新运行 CLI 或更换任务名获得新预算。
- 扩容获确认后使用新计划，但仍保留原有用量，新增额度是新上限减原用量。无需重新确认未变的方向；需要确认的是具体增加的预算。

最终报告同时说明目标缺口、结果页实际用量、详情尝试与成功读取，以及主要缺证。不得将“已用完预算”写成“市场没有岗位”。
